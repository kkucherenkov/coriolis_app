# Accessibility

The conventions every component follows. This is the **canonical** a11y
contract — durable, doctrinal, version-less. Point-in-time audit results
live separately in [`docs/A11Y_AUDIT.md`](../../docs/A11Y_AUDIT.md); when a
surface diverges from this contract, the divergence is documented inline in
the component's Storybook story or the SFC.

---

## 1. Colour & contrast

- **Body text** — WCAG AA, contrast ratio ≥ 4.5 : 1 against the surface it
  sits on. Verified for `--text-primary` (`#F2E8D0`) on `--surface-night`
  (`#15193F`) ≈ **13.0 : 1**.
- **Large text** (≥ 18 px or ≥ 14 px bold) — AA ≥ 3 : 1.
- **UI components & graphical objects** — AA ≥ 3 : 1 (button border vs
  surface, focus ring vs adjacent surface, etc.).
- `--text-secondary` (`#D9CDB0`) on `--surface-night` ≈ **9.5 : 1** — safe
  for all text sizes.

High-contrast theme (`[data-theme='high-contrast']`) overrides
`--surface-void → #000018`, `--text-primary → #FFFFFF`,
`--brand-brass → #FFD773` for AAA on critical surfaces. Persistence
contract lives in
[`README.md` § High-contrast theme](./README.md#high-contrast-theme).

Whisper accent stripe (`--chat-whisper-accent` = `--brand-indigo`)
against `--chat-bubble-other-bg` ≈ 4.0 : 1 — above the 3 : 1
graphical-object threshold; verified at 200 % zoom.

## 2. Focus

**Semantic token**: `--focus-ring` = `var(--brand-brass-light)`. Every
focusable element renders the contract below — there is no per-component
override.

```css
:focus-visible {
  outline: 2px solid var(--focus-ring);
  outline-offset: 2px;
}
```

For form inputs (`<AppInput>`, `<AppSelect>`, `<AppTextarea>`), in addition
to the ring, the border-color shifts to `--focus-ring` **and** a 2 px soft
glow is added:

```css
box-shadow: 0 0 0 2px color-mix(in oklab, var(--focus-ring) 30%, transparent);
```

Rules:

- Every focusable element has a visible focus ring. Audit-flag any
  `outline: none` without a matching `:focus-visible` replacement.
- Focus order matches visual reading order (top → bottom, left → right).
- **Never** use positive `tabindex` values. The only legal values are
  `0` (in tab order) and `-1` (out of tab order — for roving focus).

---

## 3. Roles & landmarks

Every page has **at most one** of each landmark:

| Landmark                       | Use                                                    |
| ------------------------------ | ------------------------------------------------------ |
| `<header role="banner">`       | Top app strip (`<AppHeader>`).                         |
| `<nav aria-label="…">`         | Global nav + tab strips. Every `<nav>` gets a label.   |
| `<main role="main">`           | Primary content.                                       |
| `<aside role="complementary">` | Secondary stack (player session right rail, GM tools). |
| `<footer role="contentinfo">`  | Page footer.                                           |

Within `<main>`:

- `<section>` or `<div role="region" aria-labelledby="…">` for major card
  groups.
- `<article>` for self-contained items (chat messages, characters in
  lists).

## 4. Keyboard map (canonical)

| Context                  | Key                   | Action                                      |
| ------------------------ | --------------------- | ------------------------------------------- |
| Tab strip                | `←` `→`               | Move focus between tabs (roving).           |
| Tab strip                | `Home` `End`          | Jump to first / last tab.                   |
| Tab strip                | `Enter` `Space`       | Activate focused tab.                       |
| Chat tab strip           | `Del`                 | Close a whisper tab.                        |
| Composer                 | `Enter`               | Insert newline.                             |
| Composer                 | `⌘ / Ctrl + Enter`    | Submit.                                     |
| Composer                 | `Esc`                 | Clear draft / close menu.                   |
| Message kebab            | `Enter` `Space`       | Open menu.                                  |
| Message kebab            | `↑` `↓`               | Move within menu.                           |
| Message kebab            | `Esc`                 | Close menu.                                 |
| Modal                    | `Esc`                 | Close (unless `role="alertdialog"`).        |
| Modal                    | `Tab` / `Shift + Tab` | Cycle focus within the dialog (focus trap). |
| Listbox (whisper picker) | `↑` `↓`               | Move selection.                             |
| Listbox                  | `Enter`               | Activate.                                   |
| Radio group              | `↑` `↓` or `←` `→`    | Move selection.                             |
| Radio group              | `Space`               | Select.                                     |

Roving-focus contract (tablist, listbox, radio group): exactly one item in
the group has `tabindex="0"`; the rest carry `tabindex="-1"`. Arrow keys
move both visual focus and the `tabindex` baton.

## 5. ARIA on key components

### Chat messages

- `role="article"` per message. `aria-label` is hand-crafted:
  - Whisper — `"Private message from {author} at {time}: {body}"`.
  - Broadcast — `"{author} at {time}: {body}"`.
  - System — `role="status"` instead of `article`; the body is the
    announcement.
- "Edited" / "deleted" affixes append to the label.

Message list:

- `role="log" aria-live="polite" aria-label="Messages"`.
- Reduced motion: still `aria-live="polite"`; only the transition
  animation drops.

### Tabs (`<AppTab>` family)

- Container — `role="tablist" aria-label="…"`.
- Item — `role="tab" aria-selected={active} tabindex={active ? 0 : -1}`
  (roving).

### Modals (`<AppModal>`)

- `role="dialog"` or `role="alertdialog"`.
- `aria-modal="true"`.
- `aria-labelledby="<heading-id>"` (preferred) or `aria-label`.
- Focus moves into the dialog on open; the prior focus is restored on
  close. The trap allows `Tab` to cycle within the dialog only.

### Invite reveal

- `role="alertdialog"` — explicit acknowledgement required.
- Does **not** auto-dismiss. Close requires the "I've copied it" button.

### Forms

- `<form aria-label="…">` on composer-style mini-forms that are not the
  document's primary form.
- Inputs always have an associated `<label>` or `aria-label`.
- Errors render with `role="alert"` **only on submit failure** — not on
  every keystroke.

## 6. Screen-reader copy

Things that are visible but cryptic must be voiced. Things that are
decorative must not be:

| Visible UI                    | Screen-reader text                                 |
| ----------------------------- | -------------------------------------------------- |
| `↓ 3 new messages` pill       | "3 new messages, jump to bottom"                   |
| Online presence dot           | "Online" / "Offline" — `role="img" aria-label="…"` |
| Brass `ConnectionPip`         | "Connected" / "Reconnecting" / "Disconnected"      |
| Unread count badge            | "{n} unread"                                       |
| `<AppStarOrnament>`           | `aria-hidden="true"` — decorative only.            |
| `<AppArabesqueCorner>`        | `aria-hidden="true"`.                              |
| `<AppSwash>`                  | `aria-hidden="true"`.                              |
| Skill rank dots (`<AppDots>`) | `aria-label="{rank} of {max}"` on the host row.    |

**Rule:** ornament is `aria-hidden`. Status is voiced.

## 7. Reduced motion

`@media (prefers-reduced-motion: reduce)` is a first-class state. Every
animated surface ships a reduced variant. The catalogue of verified
components lives in
[`README.md` § Reduced-motion guarantee](./README.md#reduced-motion-guarantee).
Reductions per pattern:

- No fade-in on new chat messages — instant.
- No scroll smoothing — instant snap-to-bottom on send.
- No slide-in on tab change — instant cross-fade.
- No dice-settle physics — final state appears.
- No backdrop / dialog enter animation.
- `ConnectionPip` "reconnecting" pulse → solid amber.

The reduced state is **not** "no motion" — it's "no decorative motion."
Functional cues (button hover colour shift) still happen, just at 0 ms.

## 8. Hit targets & tap zones

- **Mobile primary** — ≥ 44 × 44 logical px per Material / iOS guidance.
- **Desktop primary** — ≥ 32 × 32 (mouse) — but interactive elements with
  keyboard-only paths still meet a 44 px focus-ring envelope.
- **Dense rows** (combat tracker, skill list) — row height ≥ 44 px; action
  buttons within are 32 × 32 but the entire row is clickable.

## 9. Colour is not the only signal

Every state communicated with colour also has a non-colour cue. This is the
matrix the reviewer checks against:

| State            | Colour signal             | Non-colour signal                                                          |
| ---------------- | ------------------------- | -------------------------------------------------------------------------- |
| Connected        | Green pip                 | "Connected" label.                                                         |
| Reconnecting     | Amber pulse               | "Reconnecting…" label + pulse motion (or static dot under reduced motion). |
| Disconnected     | Red pip                   | "Disconnected" label + banner.                                             |
| Whisper          | Indigo stripe             | `WHISPER` eyebrow + screen-reader prefix.                                  |
| Crit fail        | Crimson tint              | "Crit failure" text.                                                       |
| Selected card    | Brass border              | "Chosen" chip.                                                             |
| Disabled         | Reduced opacity           | `aria-disabled="true"` + cursor change.                                    |
| Validation error | Crimson border + dot icon | Helper-text-area replaced by error message.                                |

## 10. Forms — labels, errors, hints

Every input has, in this order:

1. A visible label above (uppercase Inter — `--type-label-sm`).
2. An optional helper text below (`--text-secondary`, `--type-body-xs`).
3. Error text below — **only** after submit attempt or blur.

Rules:

- **Never** use placeholder text as the only label.
- **Never** use a disabled input as a tooltip target unless the input has a
  `title` or follow-up affordance explaining why it is disabled.
- Compose every form row through `<AppField>` so label + input + helper +
  error share one rhythm.

---

## 11. Live regions

Four live regions in the app — and only four:

| Region              | Role / live                             |
| ------------------- | --------------------------------------- |
| Chat message list   | `role="log" aria-live="polite"`         |
| Disconnected banner | `role="alert"` (assertive)              |
| Reconnecting banner | `role="status"` (polite)                |
| Toast notifications | `aria-live="polite" aria-atomic="true"` |

**Never** use `aria-live="assertive"` for non-critical updates. Audit-flag
any.

## 12. RTL readiness & non-Latin scripts

The system is LTR-first but token-clean for an eventual RTL flip:

- All directional padding uses `margin-inline-start` /
  `padding-inline-end` (logical properties). Audit-flag any
  `margin-left` / `padding-right` in `apps/web/app/**` or `packages/ui/**`.
- Icon directional affordances (the send arrow, dropdown caret) mirror
  under `[dir="rtl"]`. The icon itself does not need a separate sprite —
  use a CSS transform.
- **Forum** supports Latin only. Cyrillic falls back through
  `Cormorant Garamond Cyrillic` (production). The Forum-Cyrillic decision
  is the single open conflict between handoff and project doctrine —
  tracked in the
  [I18N design layer (forthcoming)](./README.md) of T-2026-05-14-006.
- Arabic, Hebrew, CJK are **deferred**. The token system is RTL-ready;
  the type system is not.

## 13. PR-gate audit checklist

Run through this list before signing off any surface. The reviewer cites
this section by anchor in PR comments:

- [ ] Contrast ≥ 4.5 : 1 for body text in dark **and** high-contrast
      themes.
- [ ] Visible focus ring on every focusable element.
- [ ] Tab order matches reading order.
- [ ] `role` / `aria-*` on landmarks, dialogs, lists, tabs, forms.
- [ ] Keyboard map documented for any compound interaction.
- [ ] Reduced-motion variant rendered or annotated.
- [ ] Hit targets ≥ 44 px on mobile.
- [ ] Colour-coded state has a non-colour signal (see §9).
- [ ] Screen-reader copy for cryptic visuals (see §6).
- [ ] No `aria-live="assertive"` on non-critical updates.
- [ ] Cyrillic / 1.3 × longer string fits the layout.
- [ ] No raw hex, no inline `style=""`, no `!important`.
