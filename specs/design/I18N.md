# Internationalisation — design layer

How a design surface stays honest under translation. The **engineering**
i18n contract (locale files, `t()` helpers, plural keys, Russian glossary)
lives in [`.claude/docs/i18n.md`](../../.claude/docs/i18n.md); this file is
the design-side handbook — what a designer or reviewer checks so a Cyrillic
build doesn't fall apart.

v1 ships **English (en)** and **Russian (ru)** as the proof locale.
Ukrainian (`uk`) is wired but not yet populated. Greek (`el`) is deferred —
see §6 for the consequence.

---

## 1. The `t()` contract (design view)

Every visible string passes through a translation function — `useI18n` on
web, `context.t.<namespace>.<key>` on mobile. As a designer the only thing
that matters is:

- **No literal in the design.** If the mockup has visible English text,
  there must be a parallel key with the same shape in `ru`. Ask the
  reviewer to surface the key before sign-off.
- **The longest string wins the layout budget.** Mock with the Cyrillic
  string when in doubt — see §3.

### Interpolation

Simple named variables only — `{sessionName}`, `{author}`. No nested ICU.
**Exception**: plurals are written ICU-style for `@nuxtjs/i18n` and Flutter
`slang` to consume:

```
'{n,plural,=1{message}other{messages}}'
```

Russian plurals use full CLDR (`one`, `few`, `many`, `other`) — see §4.

### Key naming convention

Dotted namespaces in `domain.subject.detail` order. Three levels in most
places; four for highly contextual strings:

```
chat.composer.placeholder.broadcast
chat.tab.session
chat.system.joined
whisper.picker.search
invite.cta.generate
session.join.revoked.title
```

**Audit rule.** Any user-visible string must trace to a `t()` call. Engineering
flags inline literals at PR review;
[`.claude/CLAUDE.md`](../../.claude/CLAUDE.md) makes "ship a user-visible
string without `t()` / `AppLocalizations`" a forbidden action.

## 2. Locale switching

- **Web** — `@nuxtjs/i18n` resolves the active locale from `Accept-Language`
  on first request, then the user's `Me.locale` preference, then the
  `<html lang>` attribute. The locale toggle in the top-nav writes the
  preference back to `PATCH /api/v1/me`.
- **Mobile** — `slang` `LocaleSettings.useDeviceLocale()` on first launch;
  the in-app picker writes back to `Me.locale` and calls
  `LocaleSettings.setLocale()`.
- **Backend** — `nestjs-i18n` resolves order:
  `QueryResolver(['lang'])` → `HeaderResolver(['x-lang'])` →
  `AcceptLanguageResolver`. Error bodies (RFC 9457) stay
  English-canonical in `title` / `detail`; only nested
  `i18n.t(...)` strings localize.

## 3. The Cyrillic stress test

Russian strings are **1.2–1.4 × longer** than their English equivalents.
This is the single most common source of layout regression. Stress samples
from the chat panel:

| EN                                   | RU                                | Ratio  |
| ------------------------------------ | --------------------------------- | ------ |
| Send                                 | Отправить                         | 1.5 ×  |
| Message everyone in The Mercy of Kua | Сообщение всем в The Mercy of Kua | 1.0 ×  |
| (edited)                             | (изменено)                        | 1.13 × |
| This message was deleted             | Сообщение было удалено            | 0.95 × |
| Whisper to Yara Zenith               | Шёпот для Yara Zenith             | 1.0 ×  |
| Reconnecting to Centrifugo…          | Переподключение к Centrifugo…     | 1.04 × |
| 3 new messages                       | 3 новых сообщений                 | 1.13 × |

### Where Cyrillic stresses layout

1. **Buttons.** "Отправить" is much wider than "Send." `<AppButton>` uses
   intrinsic width with `padding: var(--space-3) var(--space-5)`. Audit-flag
   any fixed-width button.
2. **Tab labels.** Whisper tab `max-width` is 220 px with
   `text-overflow: ellipsis`. Cyrillic display names need to truncate
   cleanly with the U+2026 ellipsis.
3. **Chip pills.** "Помолились" vs "Pushed" almost doubles the width.
   `<AppChip>` and `<AppConditionPill>` use intrinsic width with the
   composite token's tracking budget.
4. **Skill names on mobile.** "Наблюдательность" (Observation) is the
   longest stress case. The skill name column on `AppSkillRow` is `1fr`
   so it absorbs.

### `text-wrap: pretty`

Use on hero titles and any wrapping display text. The
project's Forum carries Cyrillic with metrics close to the Latin set —
`text-wrap: pretty` still helps the longer Cyrillic words ("Искандер" vs
"Iskander") avoid ragged short lines.

## 4. Pluralization

Production handles full CLDR rules — designers do not, but they should
**stress every count-bearing UI** with the four buckets. Russian buckets
for `n` are:

- `one` — `n == 1`.
- `few` — `n` ∈ {2, 3, 4} (and 22, 23, 24 …).
- `many` — `n == 0` or `n` ∈ {5, …, 20} (and 25, 26 …).
- `other` — non-integers (1.5).

### Example (production-targeted)

```jsonc
"chat.new_messages.pill": {
  "en": { "one": "↓ 1 new message", "other": "↓ {n} new messages" },
  "ru": {
    "one":   "↓ 1 новое сообщение",
    "few":   "↓ {n} новых сообщения",
    "many":  "↓ {n} новых сообщений",
    "other": "↓ {n} новых сообщений"
  }
}
```

The successes-star (`✶ U+2736`) and the `b` birr suffix from
[`CONTENT.md` § 7](./CONTENT.md#7-number-formatting-display) carry through
unchanged in every locale.

## 5. Date, time, number formatting

| Type          | Locale rule                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------ |
| Time of day   | `HH:mm` 24-hour everywhere. We do not need 12-hour. See [`CONTENT.md` § 8](./CONTENT.md#8-time). |
| Date          | `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`.                                          |
| Relative time | `Intl.RelativeTimeFormat` — "2 hours ago" / "2 ч назад".                                         |
| Numbers       | `Intl.NumberFormat` — punctuation flips per locale (`1,234` vs `1 234`).                         |
| Currency      | We use `b` (birr) as a unit suffix, not a currency code.                                         |

Mobile uses Dart's `intl` package — same locale rules; the helper lives in
`apps/mobile/lib/i18n/intl_helpers.dart` (when added).

## 6. Cyrillic glyph coverage — Forum decision

**Canonical doctrine (resolved 2026-05-14):** Forum **carries Cyrillic**.

The project ships **Forum by Denis Masharov** from Google Fonts, with
glyph coverage **Latin + Latin Ext + Cyrillic + Cyrillic Ext**. This
replaces the project's original Cinzel choice (Latin-only) — see
[`docs/DESIGN.md` § 3.1](../../docs/DESIGN.md#31-the-forum-trade-off). No
Cyrillic fallback face is configured because none is needed for the v1
locales.

### Forum vs. handoff

The handoff's `specs/design/I18N.md:110–114` documented Forum as
Latin-only with a `Cormorant Garamond` fallback for Cyrillic. **That stance
is rejected** — it predates the move from Cinzel to Forum (which expanded
the coverage). The project's `docs/DESIGN.md` is the source of truth here;
this file aligns with it.

### Locale × Forum matrix

| Locale | Status   | Display face                                      |
| ------ | -------- | ------------------------------------------------- |
| `en`   | shipped  | Forum 400 (Latin).                                |
| `ru`   | shipped  | Forum 400 (Cyrillic — Masharov subset).           |
| `uk`   | wired    | Forum 400 (Cyrillic — covers `ї`, `є`, `ґ`, `і`). |
| `el`   | deferred | **Not** Forum — Forum doesn't subset Greek.       |

### When Greek arrives

If `el` is populated, we **do not** half-fall-back. Per `docs/DESIGN.md`
§ 3.1 we swap the display face wholesale to **Cormorant Garamond** or
**EB Garamond** (both Latin + Cyrillic + Greek across multiple weights).
The partial-fallback approach is brittle and explicitly forbidden.

### Tracked nuances

- Inter — full Cyrillic + Greek + Ukrainian. No fallback needed.
- JetBrains Mono — full Cyrillic + Greek. Tabular numerals work
  identically across locales.

## 7. Right-to-left

LTR-first. RTL is **deferred** until we have a real user need. The token
system is RTL-clean today:

- Use `margin-inline-start` / `padding-inline-end` (logical properties).
  Audit-flag any `margin-left` / `padding-right` in `apps/web/app/**` or
  `packages/ui/**` — see
  [`A11Y.md` § 12](./A11Y.md#12-rtl-readiness--non-latin-scripts).
- Decorative arabesque corners flip orientation via `[dir="rtl"]`
  transforms — the icon itself does not need a separate sprite.
- The send-arrow SVG mirrors via `transform: scaleX(-1)`.

Arabic, Hebrew, CJK display-face work is **separate** from the RTL token
work — they are deferred together but not coupled.

## 8. Accessibility × i18n

Every accessibility string translates. The hand-crafted screen-reader
labels in
[`A11Y.md` § 5](./A11Y.md#5-aria-on-key-components) flow through `t()` on
production:

```ts
t('chat.aria.whisper', { author, time, body });
// → "Private message from {author} at {time}: {body}"
// → "Личное сообщение от {author} в {time}: {body}"
```

Live region announcements (`role="status"`, `role="alert"`) are voiced in
the user's locale — never in English fallback unless `ru` is missing the
key (which itself is a bug, not a fallback).

## 9. Translator notes — untranslated nouns

A few terms stay **untranslated** in every locale's UI. They are proper
nouns in the Coriolis fiction or vendor names:

- "Centrifugo" — vendor name (realtime backend).
- "Coriolis", "The Mercy of Kua", "Madara" — character/ship/setting names.
- "Forum", "Inter", "JetBrains Mono" — font names.
- "DP" (Darkness Points) in EN; "ОТ" (Очки Тьмы) in RU — abbreviation
  swaps per locale, but the underlying concept is canon.

For game-mechanic vocabulary (push → вознесение молитв, Mercy → Владычица
Слёз, etc.), the canonical Russian translations live in
[`.claude/docs/i18n.md` § Glossary](../../.claude/docs/i18n.md#glossary--non-negotiable-canon-translations).
That table is the single source of truth — drift is a review blocker.

Long-term we may add a per-session "name locale" override for GMs who run
Russian-language tables with Russian character names (e.g.
"Искандер" instead of "Iskander"). Tracked as a v2 follow-up; not in v1
scope.
